## 定义
![](https://raw.githubusercontent.com/zhongyuan202020/coder-notes-image/main/public/data-structrue/hash-table/hash-table.png)

哈希表（Hash Table）是一种基于哈希函数实现的数据结构，它通过将键值映射到表中的位置来实现高效的查找、插入和删除操作。哈希表利用哈希函数将键转换为数组索引，从而实现直接访问数据的能力。

哈希表的基本思想是将键值对存储在数组中，通过哈希函数计算键的哈希值，将其映射到数组的特定位置，从而实现O(1)时间复杂度的数据访问。

关键词：
- 哈希函数：将键转换为数组索引的函数
- 哈希冲突：不同的键映射到相同位置的情况
- 负载因子：哈希表中元素数量与表大小的比值
- 动态扩容：根据负载因子调整哈希表大小的机制

## 特点
1. 支持快速的查找、插入和删除操作，平均时间复杂度为O(1)
2. 不维护元素之间的顺序关系
3. 需要设计良好的哈希函数以减少冲突
4. 通过动态扩容保持较低的负载因子，提高性能
5. 空间利用率通常低于其他数据结构
6. 适合需要快速查找和频繁更新的场景
7. 不适合需要有序遍历或范围查询的场景

## 哈希函数
哈希函数是哈希表的核心组件，它将键映射到哈希表中的位置。一个好的哈希函数应该具备以下特性：

1. 确定性：相同的输入必须产生相同的输出
2. 高效性：计算速度快
3. 均匀分布：将键均匀地分布在整个哈希表中
4. 低冲突率：尽量减少不同键映射到相同位置的情况

常见的哈希函数设计方法：

1. 除法哈希法：h(key) = key % tableSize
2. 乘法哈希法：h(key) = floor(tableSize * (key * A % 1))，其中A为常数，通常取0.618
3. 通用哈希法：对于字符串等复合类型，可以使用如下方法：
   ```
   hash = 0
   for each character c in string:
       hash = (hash * prime + c) % tableSize
   ```
4. 密码散列函数：如MD5、SHA-1、SHA-256等，用于安全性要求高的场景

## 哈希冲突解决方法
哈希冲突是指不同的键通过哈希函数计算后映射到哈希表的同一位置。解决哈希冲突的主要方法有：

### 1. 开放寻址法（Open Addressing）
当发生冲突时，尝试在哈希表中寻找其他空闲位置存储元素。

主要变种包括：
- 线性探测（Linear Probing）：冲突发生时，按顺序查找下一个空闲位置
- 二次探测（Quadratic Probing）：冲突发生时，按二次函数的步长查找空闲位置
- 双重哈希（Double Hashing）：使用第二个哈希函数计算探测步长

优点：
- 内存利用率高，不需要额外的数据结构
- 缓存局部性好

缺点：
- 容易产生聚集现象，降低性能
- 删除操作复杂，通常需要标记删除而非真正删除
- 负载因子不能太高，否则性能急剧下降

### 2. 链地址法（Separate Chaining）
在哈希表的每个位置维护一个链表，将具有相同哈希值的元素存储在同一链表中。

优点：
- 实现简单，易于理解
- 负载因子可以大于1，更灵活
- 删除操作简单

缺点：
- 需要额外的内存存储链表节点
- 缓存局部性较差
- 在链表很长时，查找效率下降

### 3. 再哈希法（Rehashing）
当哈希表的负载因子达到阈值时，创建一个更大的哈希表，并将所有元素重新哈希到新表中。

优点：
- 保持较低的负载因子，提高性能
- 可以结合其他冲突解决方法使用

缺点：
- 再哈希过程可能耗时较长
- 需要额外的内存空间

### 4. 开放寻址的变种
- Robin Hood哈希：基于线性探测，但允许已存储的元素被新元素替换，以减少探测长度的方差
- Cuckoo哈希：使用多个哈希函数和多个表，通过元素迁移解决冲突

## 时间复杂度
<!-- 使用表格的形式展示 -->
| 操作 | 平均时间复杂度 | 最坏时间复杂度 |
| --- | --- | --- |
| 查找 | O(1) | O(n) |
| 插入 | O(1) | O(n) |
| 删除 | O(1) | O(n) |

其中，n是哈希表中元素的数量。在理想情况下，哈希表的操作时间复杂度为O(1)，但在最坏情况下（如所有键都映射到同一位置），时间复杂度可能退化为O(n)。

## 知识扩展
### 哈希表的优缺点
优点：
1. 查找、插入和删除操作的平均时间复杂度为O(1)
2. 实现简单，易于理解和使用
3. 适用于大规模数据的快速查找
4. 支持动态扩容，可以根据需要调整大小

缺点：
1. 不维护元素之间的顺序关系，不支持有序遍历
2. 不支持范围查询
3. 空间利用率通常较低
4. 性能依赖于哈希函数的质量和负载因子
5. 在最坏情况下，性能可能退化为O(n)

### 哈希表的应用场景
1. 缓存系统：如LRU缓存、内存缓存等
2. 数据库索引：用于快速查找记录
3. 符号表：编译器和解释器中用于存储变量、函数等符号
4. 集合和字典实现：如Java中的HashMap、HashSet，Python中的dict和set
5. 去重：快速判断元素是否已存在
6. 计数器：如字符频率统计
7. 分布式系统：一致性哈希用于负载均衡
8. 密码学：存储密码哈希值而非明文密码

### 哈希表与其他数据结构的比较
1. 与数组比较：
   - 哈希表支持通过键直接访问元素，数组只能通过索引访问
   - 哈希表的键可以是任意类型，数组的索引必须是整数
   - 哈希表通常空间利用率较低，数组空间利用率高

2. 与链表比较：
   - 哈希表的查找时间复杂度为O(1)，链表为O(n)
   - 链表维护元素的顺序，哈希表不维护
   - 链表的插入和删除操作不需要调整其他元素，哈希表可能需要再哈希

3. 与树比较：
   - 哈希表的平均查找时间复杂度为O(1)，平衡树为O(log n)
   - 树维护元素的顺序，支持范围查询，哈希表不支持
   - 树的空间利用率通常高于哈希表

### 常见的哈希表变种
1. 布隆过滤器（Bloom Filter）：一种空间效率高的概率型数据结构，用于判断元素是否存在
2. 计数布隆过滤器（Counting Bloom Filter）：支持删除操作的布隆过滤器变种
3. 一致性哈希（Consistent Hashing）：用于分布式系统的负载均衡，减少节点变化时的数据迁移
4. 完美哈希（Perfect Hashing）：针对静态数据集，构造无冲突的哈希函数
5. 跳跃表（Skip List）：结合了链表和平衡树的特性，可以作为哈希表的替代方案

## 功能实现
以 Java 为例，实现一个基于链地址法的哈希表。
```java
public class HashTable<K, V> {
    private static final int DEFAULT_CAPACITY = 16;
    private static final float DEFAULT_LOAD_FACTOR = 0.75f;
    
    private Entry<K, V>[] table;
    private int size;
    private int threshold;
    private final float loadFactor;
    
    // 键值对节点类
    private static class Entry<K, V> {
        final K key;
        V value;
        Entry<K, V> next;
        
        public Entry(K key, V value, Entry<K, V> next) {
            this.key = key;
            this.value = value;
            this.next = next;
        }
    }
    
    // 构造函数
    public HashTable() {
        this(DEFAULT_CAPACITY, DEFAULT_LOAD_FACTOR);
    }
    
    public HashTable(int initialCapacity) {
        this(initialCapacity, DEFAULT_LOAD_FACTOR);
    }
    
    @SuppressWarnings("unchecked")
    public HashTable(int initialCapacity, float loadFactor) {
        if (initialCapacity < 0) {
            throw new IllegalArgumentException("初始容量不能为负数");
        }
        if (loadFactor <= 0 || Float.isNaN(loadFactor)) {
            throw new IllegalArgumentException("负载因子必须为正数");
        }
        
        this.loadFactor = loadFactor;
        this.table = new Entry[initialCapacity];
        this.threshold = (int) (initialCapacity * loadFactor);
        this.size = 0;
    }
    
    // 计算哈希值
    private int hash(K key) {
        return key == null ? 0 : Math.abs(key.hashCode()) % table.length;
    }
    
    // 查找操作
    public V get(K key) {
        int index = hash(key);
        Entry<K, V> entry = table[index];
        
        while (entry != null) {
            if (key == null ? entry.key == null : key.equals(entry.key)) {
                return entry.value;
            }
            entry = entry.next;
        }
        
        return null;
    }
    
    // 插入操作
    public V put(K key, V value) {
        int index = hash(key);
        Entry<K, V> entry = table[index];
        
        // 检查是否已存在相同的键
        while (entry != null) {
            if (key == null ? entry.key == null : key.equals(entry.key)) {
                V oldValue = entry.value;
                entry.value = value;
                return oldValue;
            }
            entry = entry.next;
        }
        
        // 添加新节点到链表头部
        table[index] = new Entry<>(key, value, table[index]);
        size++;
        
        // 检查是否需要扩容
        if (size > threshold) {
            resize(2 * table.length);
        }
        
        return null;
    }
    
    // 删除操作
    public V remove(K key) {
        int index = hash(key);
        Entry<K, V> prev = null;
        Entry<K, V> entry = table[index];
        
        while (entry != null) {
            if (key == null ? entry.key == null : key.equals(entry.key)) {
                if (prev == null) {
                    table[index] = entry.next;
                } else {
                    prev.next = entry.next;
                }
                size--;
                return entry.value;
            }
            prev = entry;
            entry = entry.next;
        }
        
        return null;
    }
    
    // 扩容操作
    @SuppressWarnings("unchecked")
    private void resize(int newCapacity) {
        Entry<K, V>[] oldTable = table;
        table = new Entry[newCapacity];
        threshold = (int) (newCapacity * loadFactor);
        
        // 重新哈希所有元素
        for (Entry<K, V> entry : oldTable) {
            while (entry != null) {
                Entry<K, V> next = entry.next;
                int index = Math.abs(entry.key.hashCode()) % newCapacity;
                entry.next = table[index];
                table[index] = entry;
                entry = next;
            }
        }
    }
    
    // 获取哈希表大小
    public int size() {
        return size;
    }
    
    // 判断哈希表是否为空
    public boolean isEmpty() {
        return size == 0;
    }
    
    // 清空哈希表
    public void clear() {
        Arrays.fill(table, null);
        size = 0;
    }
    
    // 获取所有键
    public Set<K> keySet() {
        Set<K> keys = new HashSet<>();
        for (Entry<K, V> entry : table) {
            while (entry != null) {
                keys.add(entry.key);
                entry = entry.next;
            }
        }
        return keys;
    }
    
    // 获取所有值
    public Collection<V> values() {
        List<V> values = new ArrayList<>();
        for (Entry<K, V> entry : table) {
            while (entry != null) {
                values.add(entry.value);
                entry = entry.next;
            }
        }
        return values;
    }
    
    // 判断是否包含指定键
    public boolean containsKey(K key) {
        return get(key) != null;
    }
    
    // 判断是否包含指定值
    public boolean containsValue(V value) {
        for (Entry<K, V> entry : table) {
            while (entry != null) {
                if (value == null ? entry.value == null : value.equals(entry.value)) {
                    return true;
                }
                entry = entry.next;
            }
        }
        return false;
    }
}
```
